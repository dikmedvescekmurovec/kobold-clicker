## Map code (`Scenes/Map/`)
| File | Contents |
|---|---|
| `hex_grid.gd` (`HexGrid`) | Pointy-top offset grid with odd rows shifted right (same as the TileMapLayers). `Edge` enum (E, SE, SW, W, NW, NE) and `EDGES`, `neighbor`, `neighbors`, `opposite`, `distance`, `corners`, and the edge bitmask pair `edge_mask` / `mask_edges` that roads are described with |
| `sheet_meta.gd` (`SheetMeta`) | Reads `AI-sprites/spritesheet/hex_tileset.json` once per run and hands out its `meta` block, so nothing restates the rules the sprites were drawn to. `env_adjacency()` is the adjacency table, with each environment's self-entry stripped |
| `hex_tileset.gd` (`HexTileset`) | Builds the TileSet at runtime from `AI-sprites/spritesheet/hex_tileset.json` (56×64 tiles). `atlas_coords`, `road_name`, `blend_name`, `env_rank`, `can_border`, `opaque_mask` |
| `hex_map.tscn` / `hex_map.gd` (`HexMap`) | GroundLayer, one `Blend_<env>` layer per spreading environment (created in `_ready`), RoadLayer, Highlight. `set_ground` redraws the blends of the cell and its neighbors, reading the environment of cells that aren't drawn yet through the `hidden_env` Callable, so a tile looks the same however late it is charted. `get_tile_info` includes `blends` and `environments` (visible pixel share per environment). Owns the `fog` overlay and the `player` token. Signals `tile_hovered`, `tile_clicked`, and `dragged` (mouse movement while dragging, for the owner of the camera). A click selects a tile; a press that travels more than `DRAG_THRESHOLD` pans instead. `set_player_cell` moves the player token |
| `player_token.gd` (`PlayerToken`) | The player's character, an `AnimatedSprite2D` with an "idle" and a "run" animation from `Assets/Player`. The sheets' frames are wide (room for the attack swing), so one `BOUNDS` crop, the union over both sheets, cuts every frame down to the character; sharing it keeps the character still when the animation changes. Drawn at `SCALE` (half size). `walk(path)` runs it from tile to tile at `SECONDS_PER_TILE`, `advance(delta)` steps that on (tests drive it directly), `finish_walk()` jumps to the end, and `arrived` fires on the last tile. `HexMap` creates it in code, after the highlight, so it draws on top |
| `fog_overlay.gd` (`FogOverlay`) | The translucent grey hex drawn over every tile that is seen but not charted. `HexMap` creates it in code, between the roads and the outlines |
| `hex_highlight.gd` | Hover and selection outlines: a bright band with a dark ink border, readable on every terrain |
| `environment_generator.gd` (`EnvironmentGenerator`) | Random-frontier growth under `ALLOWED`: prefers neighbors, boosts regions under `MIN_REGION_SIZE`, damps regions over `MAX_REGION_SIZE`, then merges small regions. `extend()` grows an existing map into new cells without touching the old ones (they are frozen against merging), which is how the map enlarges. Tunables are at the top |
| `town_world.gd` (`TownWorld`) | 256×256 world of towns (small 1%, medium 0.5%, fortress 0.1%, never on neighboring spots). Each town links to its 1/2/4 nearest towns (small/medium/fortress) within 20 steps, in both directions. `to_dict`/`from_dict` are the map save's copy of the whole world -- towns as flat `[x, y, tier]` against a legend of tier **names**, links once per pair with the lower spot first, and `_buckets` rebuilt rather than stored. It is written down rather than regenerated because "a pure function of its seed" is a property of this code today and not a promise to the player |
| `road_network.gd` (`RoadNetwork`) | Routes roads along the town links with A*, using only shapes the sprites have (straight, 120° curve, 3/4/6-way). Roads stop at town edges and never cross a town tile. Terrain-independent, so a world always gives the same roads. `extend()` adds the links a window brings into reach, routing each inside its own box (around its two towns), so a road never moves once laid — growing the map only ever adds edges, sometimes turning a drawn road into a junction |
| `map_builder.gd` (`MapBuilder`) | Generates the map (`START_RECT`: 20×11 cells around cell (0, 0), which the camera centers on screen) and draws it as the player uncovers it. `rect` is what the map covers now: coming within `EXPAND_MARGIN` of an edge grows it by `EXPAND_BY` on that side (`expand_if_needed`, on arrival), generating the new land, its tiles and the roads it brings into reach, and redrawing the blends and roads of drawn tiles the new land touches. Everything already generated stays exactly as it is. Every cell is in one `State`: `HIDDEN` (the fog of war, nothing drawn), `UNCHARTED` (drawn under the grey fog, can't be walked to) or `CHARTED`. `create()` generates everything and draws `start_cells()`: the charted center, where the player starts, ringed by six uncharted tiles. `chart(cell)` takes the grey off a tile next to the player (`can_chart`), draws the tiles behind it as uncharted, and sends the player walking onto it. `name_of(cell)` is what the tile is called: `_show` names it the first time the player lays eyes on it -- uncharted land is land they can see, so seeing it is the encounter -- and the name is kept in `_names` and written into the save. It is stored rather than worked out again even though `TileNames.generate` is a pure function of the seed and the cell, for the reason the town world is written down: a place somebody has fought over must not be renamed by a later build widening a word list. `level_of(cell)` is the tile's level, in bands that widen as they go (band `n` is `n` tiles wide, so level `n` starts at the nth triangular number) -- what the side panel shows and the ceiling on what can drop there. `area_variant(cell)` says which battle backdrop the tile fights on -- its town tier if it has one, else `road` where a road runs, else `plain`. `can_farm(cell)` is any charted tile with no walk under way -- farming asks nothing about where the player stands, because a run is a thing you choose to do rather than a step you take. `move_to(cell)` sends the player walking to a charted tile over `route_to(cell)`, a shortest path of charted tiles (`can_move_to` refuses anything else, and anything at all while `walking`); arriving emits `arrived(cell)` and charts nothing by itself. `reveal_all()` charts the lot. `origin` is the world spot at cell (0, 0): generated environments, plus that environment's town sprite where the world has a town. Before drawing, it clears any town within `START_TOWN_DISTANCE` (5) of the center and guarantees a small town exactly that far out, which a road links to cell (0, 0); that town's world spot is `start_town`. `_spot(cell)` is the crossing from map cells to world spots. `to_save()` and `restore()` are the map save's two ends: `restore` is the mirror of `create` and shorter than it, because the saved town world already has the clearing and the start town in it and the start road is among the saved roads, so it generates nothing and touches no town. It draws through `_draw_saved`, which lays every ground and road down first and refreshes each cell's blends once, rather than through `_show` -- `set_ground` refreshes a cell **and its six neighbours**, which is seven times the work when a whole map arrives at once |
| `tile_names.gd` (`TileNames`) | What a tile is called: a made-up proper word (a head syllable and a tail one, five hundred pairs) and a feature word taken from the environment, or from the settlement's tier where there is one -- "Bralmere Keep" says more about a fortress than "Bralmere Meadow" does. `generate` is a pure function of the map seed and the cell, under its own `"name"` tag, so what a place is called has nothing to do with which sprite it is drawn with or which backdrop it fights on. It names neither `MapBuilder` nor `TownWorld` -- the caller passes the environment and the tier's name -- so it is a table and a dice roll and nothing else |
| `map_save.gd` (`MapSave`) | The explored map at `user://map.json`: the seeds, the origin, the window, the whole town world, the land, the roads, the names of the tiles the player has seen, and what they have uncovered and where they stand. Version 2 added the names, written out as a plain `"x,y"` object rather than as rows against a legend -- a name is a whole word per cell and only the cells that have been looked at have one, so there is nothing for the alphabet to index; a version 1 save simply has none and its tiles are named again as they are asked about. `_tiles` and the fog are left out, being derived. The environments and the states are **one string per map row, one character per cell**, each indexing a legend written beside it -- which keeps the save small, keeps enum positions off the disk, and makes the env rows read as a picture of the map. `fingerprint(tileset)` is the SHA-256 of the three spritesheet tables a saved map is *read through* (`env_adjacency`, `blend_priority`, `legal_road_masks`) and nothing else, so a rebuilt sheet that only adds a variant costs nobody their map. `load_from` returns **two different nulls**: an empty `problem` is a first run, and a reason in it is a refusal. Never names `MapBuilder` -- that is the cycle Godot's checker bites on, so the states are raw ints here and `STATE_NAMES` is the legend |

## Rules and gotchas
- **Rules come from the JSON meta:** `blend_rule`, `blend_priority` and `env_adjacency`, all read through `SheetMeta` — `HexTileset.can_border` and `EnvironmentGenerator.allowed()` are the same table, so the generator cannot produce a border the sprites can't draw.
- **Map origins must be on even rows**, otherwise world neighbors don't match on-screen neighbors (`MapBuilder` asserts this).
- **Nothing on the map changes, so nothing on it is regenerated.** Both map generators are order-dependent, not seed-dependent: `EnvironmentGenerator.extend` seeds its frontier from the order cells were inserted, and `RoadNetwork._route` routes into the roads already laid and abandons a route that would merge illegally. So the same seed and the same final rect do *not* give the same land -- only replaying the identical sequence of windows would, and that would weld every save to one build of the generator. The town world is written down too, though it is a pure function of its seed today, because that is a property of the current code rather than a promise to the player.
- **A tile is named once, and the name is written down.** `MapBuilder._show` names every tile the moment it comes out of the fog and never again, and `MapSave` carries the names rather than regenerating them on load. `TileNames.generate` being a pure function of the map seed and the cell is a property of today's tables, not a promise to the player -- widening a word list or adding a seventh environment would otherwise rename places somebody has already fought over. The fight's HUD is the one place a name is read, so a rename would be read as a different tile.
- **A save that cannot be honoured stops, and is never written over.** Refusing and then generating a fresh world would destroy the old save on the first arrival, which is the one outcome worse than an error message -- the same reason `Inventory` leaves a newer-version file alone. Only a *missing* file means a new world, which is why `MapSave.load_from` has two different nulls.
