## Skills (`Scenes/Skills/`)
**The player calls them skill nodes** (the user's rename, 2026-10-09: "Strength Node", the bag's "Skill nodes" tab, `LootTable.RENAMED` carrying old saves over); the code still says stone (`is_stone`, `stone_tier`, the slot `"stone"`, the save's keys).
The player's own skill tree (the user's design, 2026-10-08; the why is `DESIGN.md`), grown out of a fixed root from **skill stones**: items that drop and are crafted like gear and are placed only on the black screen of a transcension. Every level past the first is one skill point, spent as a rank in a placed stone. The points are **not stored**: the free points are `Skills.earned(level) - spent()`, so a save can never disagree with itself.

## Rules and gotchas
- **Skills stack around the gear's globals, not into them.** `Equipment.totals(skill_flat, skill_percent)` adds the pieces, then the skill flats, then applies the gear's `GLOBAL` percents, then the skills' percents as a **separate** multiplier -- so a stone's flat damage is scaled by a ring like the sword's own, and a ring's 10% and a stone's 10% make 21%. `totals()` with nothing passed is the set alone.
- **The tree's attributes go into `Inventory.attributes()` with the gear's, before the Echo, the Crown and the Brand, and never at `skill_worth`** -- the Abacus reads intelligence to work that out. `gear_attributes()` (what achievements ask) stays the gear's alone. A fresh tree holds no point and adds nothing, so a fresh hero's attributes are the gear's.
- **The tree is kept, the points are not**: `Inventory.transcended` copies `tree_dict()` and starts the ranks over with the level. A stone is changed only on the black screen (`Inventory.place_stone`, `BagPage`'s stones mode); what a swap pushes out goes to the bag and is lost with it. Placed stones are frozen: they never climb like heirlooms.
- Ranks on stones: `Inventory._tree()` hands the sums the Abacus's IV (a rank more on every stone holding one) and a helmet's `<attribute>_stones` line (ranks more on that base's). The Specialist curse is one **branch** (`branch_of`), checked in `Inventory.why_not_skill`; the root is on none, so it neither is refused nor refuses. **With the root's one slot there is one branch, so the Specialist refuses nothing** and is only its half-again worth (unruled); `test_inventory` stands two branches in by hand to keep the rule checked.
- Saved as `skill_tree` (path -> the stone's own save) and `skill_ranks` (save version 33); a save from before has no tree and starts from the starter, every point free.
