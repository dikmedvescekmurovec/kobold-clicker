# Kobold Clicker: An Idle Loot RPG

(Once "Incremendal Side Scroller": `project.godot` pins the save folder to that old name so existing saves still load.)

Godot 4.7 (GDScript) incremental game. Current work: a clickable, procedurally generated hex map drawn with AI-generated pixel-art sprites.

## Commands
Use the console build, so output reaches the terminal: `C:\Users\Dik\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe`. The 4.5.1 exe on the Desktop is too old for this project.

|---|---|
| **All tests** (run before calling anything done; about a minute, the suites side by side) | `python tests/run_all.py` |
| Some suites, by name or the start of one (`inventory`, `combat` and `town` are several suites each, `test_<name>_<part>.gd`, and the name runs them all) | `python tests/run_all.py combat inventory` -- `hex_map` (map, tileset), `generation` (generation, towns, map builder, map save), `ui_theme`, `enemies` (roster, sprite geometry), `combat`, `skills`, `inventory` (loot, rarity, inventory, save, heirlooms, achievements), `town` (services, prices, selling, buying, vendor stock, town state, bounty board, fortuneteller, transcending), `cloud` (what a sync decides, the account file, the question, a sync against scripted replies), `camp` (rates, earnings, the save), `big_number`, `characters` (the roster's art, each hero in a fight and on the map, buying and picking and their save, the page), `main` (when the scene may save and when it refuses, a closed window, fights opened and left, tips, pages and their keys, the settings' round trip, the web's music), `ui_pages` (every page built at a monitor's and three phone shapes and held to the layout rules; `KOBOLD_LAYOUT_DUMP=<folder>` writes each as JSON) |

**The runner is the only way to run a suite.** It gives each suite a `user://` folder of its own (a temp `%APPDATA%`), so no suite can reach the player's saves or another run's scratch files, and it fails a suite on a non-zero exit, a `SCRIPT ERROR`, an engine `ERROR:` line (a null `load()`, a freed capture), a missing "All ... tests passed" line or a timeout -- Godot exits 0 when a script a suite depends on does not parse, so a bare exit code lies. It refuses to start while a `_test_*` function is defined and not called with its result checked. Each suite's whole output is kept in `%TEMP%\kobold_tests\<suite>.log`. (A raw `<godot> --headless --path . -s res://tests/test_<suite>.gd` shares the real `user://`; the harness fails a suite that touched the player's own files.)

"UID duplicate" warnings come from duplicated asset folders under `Assets/` and are harmless.

## Where things are documented
Each code folder has its own `CLAUDE.md`: a one-line description per file plus that area's rules and gotchas. It loads automatically once a file in that folder is read, so **read the source file before changing it or explaining it**. Beside most of them is a **`DESIGN.md`** holding the long-form reasoning (why the UI is laid out as it is, what was tried and turned down, how the balance is meant to feel). It is *not* loaded automatically: **read it before changing how something is meant to work, and put new reasoning there, not in `CLAUDE.md`** -- keep each `CLAUDE.md` to short rules. **A folder's `CLAUDE.md` is a table of its files, one line each, and its rules, two sentences each at most; each rule's full text is in that folder's `DESIGN.md`** -- under "Reference" at that file's end, beside every file's long description, under a heading that is the rule's own bold title unless the rule names another (`(DESIGN.md: "...")`). Read that heading before leaning on a rule's fine print, and when a rule changes, change both. `tests/` has no notes of its own: before editing a test, read the source it tests; the suites that were split share their helpers in `tests/<name>_base.gd`, and `tests/fixtures/inventory_golden.json` is a whole save every later build must still read (the inventory suites and the backend's `npm test` both hold it). Before a change that spans areas (a fight's loot reaching the bag, a stat reaching combat), read `Scenes/CLAUDE.md`, which holds the cross-cutting rules.

## Sprites
The sprites are generated by `AI-sprites-generator/` (Python, exported through Aseprite). Its README holds the palette, geometry, adjacency table and blend rules. `AI-sprites/` is build output: change the generator, preview with `qa.py` and get the user's approval, then run `build.py`.
**The interface is in ENDESGA 64** (since 2026-09-30): every sprite the tools write to `Assets/UI/` goes through `hexlib.to_e64`, and every colour in `Scenes/UI/palette.gd` is one of its 64 (`test_ui_theme` checks both). Map tiles, gear, orb, skill and spell icons and portraits keep their own palettes.
Generated sets (hex tiles, backdrops, slimes, the health bar, the old gear icons the pixellab pieces replaced): `AI-sprites-generator/CLAUDE.md`. Sprites cut from bought packs (UI theme, pips, gear, orbs, skill icons, loot beam): `tools/CLAUDE.md`.

## Rules and gotchas
- **Balance is the user's, by hand** (2026-09-27): no balance tables or simulations, and no test that pins difficulty, pace, prices or drop rates -- a test checks that a rule works (a formula, an order, a save), never that a number is tuned right. The `DESIGN.md` notes that mention `tests/balance_*.gd` or frontier pins are history; those are gone.
- **Test pattern:** everything in `tests/` extends `tests/harness.gd`, which starts `_run` deferred and holds `_check`, the failure count, `_report("suite name")` and the shared `WORLD_SEED`. Each `_test_*` function returns `true` and `_run` checks that it did (`_check(_test_x() == true, "...")`, with `await` inside for one that awaits), so a script error counts as a failure; the runner refuses a suite with a test that is not called that way.
- **Editor conflicts:** the Godot editor is often open. After changing `project.godot` or `.tscn` files outside it, reload the project so the editor doesn't overwrite them.
- **Every window is drawn at its own pixels at a whole `ui_scale`** (`UITheme.pick_scale`: the largest that leaves the 576x324 panel-pixel budget; the main scene turns the project's stretch off at run time, except headless, where the tests lay out against it). **A window under 576 panel pixels across -- only ever one held upright -- is narrow** (`UITheme.narrow`): every page and the tile panel is a sheet along the foot -- centred at its own width, as tall as what it holds and never more than half the window -- over a corner row, and a town is its page over the bag. The default 1152x648 window is pixel for pixel what it was. Rules in `Scenes/UI/CLAUDE.md`, the why in `Scenes/UI/DESIGN.md`.
- **Pixellari renders cleanly only at 16 px**, its native size; below about 14 the glyphs break up. To make the interface smaller, lower `ui_scale` rather than the theme's `FONT_SIZE`. **Body text (stat lines, modifiers, card bodies, sentences) is Ark Pixel at its native 10 px** (`UITheme.SMALL_FONT`, the `SmallLabel` variation); names, headings and button faces stay Pixellari.
- **A `Control`'s `size` is clamped to its minimum as it is set, and a `TextureRect`'s minimum is its texture until `expand_mode` says otherwise.** So asking a 32 px icon for a 16 px size while the mode is still the default gets 32, and lowering the minimum afterwards does not shrink what was already set -- `OrbSlot` sets `expand_mode` and `stretch_mode` *before* the texture and the size, and the orbs drew at double size until it did.
- **`set_anchors_preset(PRESET_FULL_RECT)` on a Control already in the tree keeps its current rect** (0x0 for a new one) and then grows only by however much the parent grows: use `set_anchors_and_offsets_preset`, or set the preset in `_init`. The password prompt centred on a 29x51 box at the top-left when a phone's keyboard opened.
- **The web export needs `html/experimental_virtual_keyboard=true`:** without it Godot types through a hidden IME box that reads only composition events and real keys, and a phone's keyboard sends neither (keydown 229 "Unidentified", the text in `input` events), so nothing typed on a phone lands in a `LineEdit`.
- **A lambda captures by value, and so is a `PackedStringArray`:** anything a test gathers from a signal has to be collected in an `Array`, which is shared, or the count outside the lambda never moves.
- **Saves are written through `SafeFile` (`Scenes/safe_file.gd`) and a save that cannot be read is refused, never overwritten:** `SafeFile.write` goes to `<path>.tmp` and renames, `SafeFile.recover` runs before a read. `Inventory.load_from` and `MapSave.load_from` both report a bad file through a `problem` array, and `main_scene._ready` stops on either (`_refuse_save`) before anything can write.
- **`Assets/Potential/` carries a `.gdignore`:** its bought packs are for `tools/` to cut from, and anything the game `load`s must live elsewhere -- a path in there loads as null with only a logged `ERROR` (the map's chest drew invisible that way; the test runner has failed a suite on any `ERROR:` line since 2026-10-10).
- **`.claude/settings.json` (tracked) checks every script an agent edits and asks before a deploy:** its `PostToolUse` hook runs `python tools/check.py --hook` after an Edit or Write, which says nothing unless the `.gd` just written no longer parses, and its `ask` rules put a question in front of `npm run deploy`, `wrangler deploy`, any `wrangler ... --remote` and `tools/web.py --deploy`. A deploy is the user's to ask for, never a step of some other task.
- **The code and its comments are read only by agents** (the user's, 2026-10-10): keep a comment only where an agent changing the code would err or have to re-derive something costly without it -- a why, an invariant, an engine quirk, a contract with another file, a ruling of the user's with its date -- and put long reasoning in the folder's `DESIGN.md`. No line over 120 characters (a tab counts as one), in GDScript or Python.
- **Commit** `.uid` and `.import` files.
